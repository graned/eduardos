# Running eduardOS in a VM (early prototype)

**Stage:** v0.1 foundation — not a distributable installer or production OS.

## Requirements

- A Linux host with Nix and flakes enabled.
- x86_64 hardware, QEMU/KVM, and hardware virtualization enabled.
- Around 4 GB free memory for the guest, plus space for Nix builds.

## Build

From a clean clone:

```sh
nix flake check
nix build .#vm
```

This is designed to build NixOS's QEMU VM launcher rather than an ISO.
The `flake.lock` pins the NixOS 26.05 package input.

## Run

```sh
./result/bin/run-eduardos-vm-vm
```

The launcher name is generated by NixOS and can vary by configuration;
if the command above is not present, inspect `ls result/bin/` and run the
`run-*-vm` launcher.

Log in as user `forge`, password `forge`, **for VM testing only**.
On a TTY, try `start-hyprland` (the Hyprland/UWSM entry point).
Wayland compositors can require working QEMU graphics acceleration;
if the compositor fails, capture its error output rather than modifying
the physical host.

The QEMU launcher creates a writable QCOW2 disk in the working
directory. Reusing it retains previous guest state; back it up or
remove it deliberately when testing a clean boot.

## Milestone acceptance checks

- [ ] `nix flake check` passes
- [ ] `nix build .#vm` succeeds on Linux
- [ ] VM boots and console login works
- [ ] Hyprland starts within the virtual GPU limitations
- [ ] Ghostty/Fuzzel/Waybar can launch
- [ ] Firefox launches and PipeWire audio works where guest audio is supported

**Not implemented yet:** custom installer, Disko, persistent Btrfs
subvolumes, Home Manager, OpenCode, Isenguard, container engine selection,
`edos`, and custom visual theme. Those arrive in later milestones.

## Security

Never reuse the test password on real hardware, never expose the test
VM to untrusted networks, and don't rely on this configuration as a
hardened distribution.
