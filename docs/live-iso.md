# eduardOS Alpha 0.1 — Live ISO (PR #18)

The first live image is an **experimental, non-destructive preview** of
eduardOS. It boots the Forge Neon/Tlaloc Hyprland desktop from a read-only
ISO with a writable temporary overlay.

It is **not an installer**: there is no guided disk selection, partitioning,
encryption setup, or supported install-to-disk flow. The existing
`eduardos-uefi-lab` Disko fixture is deliberately NOT imported.

## Recommended build on Apple Silicon macOS (Docker + nixbuild.net)

With Docker Desktop, a private SSH key registered with nixbuild.net,
and no host Nix installation:

```sh
export NIXBUILD_SSH_KEY="$HOME/.ssh/eduardos_nixbuild"
docker compose -f builder/compose.yml run --build --rm iso
```

The ISO lands in `out/eduardos-alpha.iso`; see
[`docs/docker-builder.md`](docker-builder.md) for one-time setup,
security notes, required Docker disk capacity and troubleshooting.
Remote builds still use nixbuild.net CPU-hour credits. This is our
preferred macOS workflow; GitHub Actions remains optional.

## Build on a Linux machine with Nix

Requirements: x86_64 Linux, Nix with flakes enabled, enough disk space
for a Nix store and the ISO (allow ~30–50 GiB free to start), and preferably
8 GiB RAM. The full ISO build is intentionally not part of the ordinary PR
merge gate.

```sh
git clone https://github.com/graned/eduardos.git
cd eduardos
git switch main

nix --extra-experimental-features 'nix-command flakes' \
  build -L .#checks.x86_64-linux.live-iso-config

nix --extra-experimental-features 'nix-command flakes' \
  build -L .#live-iso

ls -lh result/iso/*.iso
```

The output is a symlink at `result/iso/*.iso`. Copy the ISO to a stable
path before removing the `result` symlink or collecting Nix garbage.

## Build with GitHub Actions

After this PR is merged to `main`, open
**Actions → eduardOS Alpha live ISO → Run workflow** and select a branch.
The manual job uploads ISO chunks and a SHA256 checksum as the
`eduardos-alpha-live-iso` artifact (seven-day retention).

After downloading and extracting the artifact:

```sh
cat eduardos-alpha.iso.part-* > eduardos-alpha.iso
sha256sum -c SHA256SUMS
```

These files must be reconstructed in a common directory. The workflow
splits larger images into chunks to make individual uploads manageable.

## Boot it safely in QEMU/KVM

For a first manual test, use **virt-manager** on Linux:

1. Create a new x86_64 virtual machine using the ISO as install media.
2. Prefer UEFI/OVMF firmware, 4 vCPUs, 6–8 GiB RAM and a VirtIO graphics
   adapter. Enable 3D acceleration if supported by the host.
3. **Do not attach any existing host disk or raw block device.** A VM
   with no writable disk is sufficient for this live-image test.
4. Boot the ISO. If supported by the VM's graphics backend, greetd
   automatically starts Hyprland as the temporary `forge` user.
5. Try Super+Return (Ghostty), Super+D (Fuzzel), Waybar and the Tlaloc
   wallpaper. Confirm NetworkManager and basic keyboard/mouse input.

Optional CLI boot (desktop Linux with QEMU/KVM; no virtual disk):

```sh
qemu-system-x86_64 \
  -enable-kvm -machine q35 -m 6144 -smp 4 \
  -cdrom eduardos-alpha.iso -boot d \
  -vga virtio -display gtk \
  -nic user,model=virtio-net-pci
```

This example uses the default BIOS firmware; use virt-manager with
OVMF to explicitly validate UEFI boot. Hyprland's requirements can
exceed the capabilities of unaccelerated QEMU graphics. A black screen
or compositor failure may indicate the VM's Vulkan/OpenGL renderer
needs adjustment; it does not prove the ISO or storage system failed.

## Acceptance checklist

- [ ] ISO is generated by Docker+nixbuild.net, manual GitHub workflow, or local `nix build`
- [ ] ISO boots in a clean VM (preferably OVMF/UEFI)
- [ ] Live session reaches Hyprland without manually installing packages
- [ ] Forge Neon wallpaper and Waybar render
- [ ] Ghostty, launcher, keyboard and pointer work
- [ ] NetworkManager provides connectivity
- [ ] Reboot returns to the untouched live environment
- [ ] No physical disks were modified

The live user is `forge` with password `forge` for recovery/login
purposes, and passwordless sudo in this **disposable ISO only**. Never
reuse these credentials for a real install.

## Known limits and next milestone

This PR provides an ISO build recipe and live session configuration.
Until an ISO has built and been booted successfully, **bootability and
graphical auto-login remain unverified**. It doesn't include a
general-purpose graphical installer, persistent live USB storage, safe
disk picker, recovery UX, or hardware certification.

Next: validate a real ISO artifact and VM boot, then build a safe
interactive installer as a separate milestone.
